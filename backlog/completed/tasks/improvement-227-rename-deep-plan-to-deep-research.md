# improvement-227: Rename deep plan to deep research

**Type:** improvement — naming of an existing command and agent
**Module:** `.claude/` (`commands/deep-plan.md`, `agents/planning/deep-planner.md`, `agents/planning/README.md`, `agents/README.md`, `commands/README.md`, `commands/optimize.md`, `nav/flows.md`), root `CLAUDE.md`, `backlog/research/tools/` (README and scripts' wording)
**Priority:** 🟡 Top — first in the backlog, at the user's request (2026-10-26).
**When:** independent; start it when no `deep-planner` run is in flight, because the agent name is its registered type and a running or queued run still uses the old one.

## Current state

The in-depth planning mechanism is called "deep plan": the slash command `/deep-plan` (`.claude/commands/deep-plan.md`), the subagent `deep-planner` (`.claude/agents/planning/deep-planner.md`, with `.claude/agents/planning/README.md`), and the wording "plan"/"planner" inside the brief template and the reply words `PLAN READY` and `PLAN BLOCKED`. The working folders already live under `backlog/research/` and the tool scripts under `backlog/research/tools/`, so the folder says "research" while the command says "plan". The old name appears in 9 tracked files outside the completed tasks and generated pages (27 mentions): the agent and command README files, `.claude/commands/optimize.md` (which starts the agent), `.claude/nav/flows.md`, root `CLAUDE.md` (the slash-command list and the agent list), and the open task `improvement-226`. The generated architecture map reads the command and agent names and is regenerated by `bash docs/architecture/scripts/generate-architecture-model.sh`.

## Why change

The mechanism studies the web and the project, compares choices and ends in a recommendation and two plans; the plan is one of its products, not its nature. "Deep research" says what it does, matches the folder name, and avoids the confusion with the Approval Rule's own "plan" that every task already needs.

## Expected benefit

One name for one thing: the command, the agent, the folder and the documents agree, and a reader looking for "research" finds it. No change in behaviour.

## Approach

1. **Full rename (recommended to price first):** command `/deep-research`, agent `deep-researcher` (file and frontmatter `name`), README titles and the navigation row in `.claude/nav/flows.md`, root `CLAUDE.md`, `.claude/commands/optimize.md`, the description strings, the `Agent({description: "Deep research <topic>", subagent_type: "deep-researcher", ...})` example, and the open task `improvement-226`. Keep the folder `backlog/research/` and its scripts as they are. Decide whether the reply words `PLAN READY`/`PLAN BLOCKED` stay (they name the produced plan, which still exists) or become `RESEARCH READY`/`RESEARCH BLOCKED`; the scripts and the command parse them, so they change together or not at all.
2. **Command only:** rename `/deep-plan` to `/deep-research` and keep the `deep-planner` agent name; smaller, but leaves two names for one mechanism.
3. **Wording only:** keep every identifier and change the descriptions; cheapest, solves nothing for the identifiers.
4. Whatever is chosen: completed tasks, the observations log and archived history keep the old name (history is not rewritten); the architecture model is regenerated; the registered agent type changes only when no run is in flight; check `grep` for the old names across `.claude/`, root `CLAUDE.md`, `backlog/` (open tasks), `docs/` and `scripts/` before and after, and run the `check-flows-completeness` check if present.
