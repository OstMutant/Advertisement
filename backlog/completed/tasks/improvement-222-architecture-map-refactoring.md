# improvement-222: Architecture map refactoring — first item: remove Mermaid from `architecture-map.html`

**Type:** improvement — refactoring of a generated developer tool
**Module:** `docs/architecture/scripts/generate-architecture-model.sh` (holds the page template and writes `docs/architecture/architecture-map.html`), `docs/architecture/architecture-map.html` (generated output), `docs/architecture/data/architecture-model.json`
**Priority:** closed 2026-11-04 (was medium — larger tech debt, no live bug)
**When:** closed 2026-11-04, see `## Closure`

## Current state

Verified 2026-10-23 against `docs/architecture/architecture-map.html` (3,894 lines, 885 KB; its template is inside `generate-architecture-model.sh`, the HTML is regenerated by that script).

- The page loads four scripts from the network (`unpkg.com`): `cytoscape@3.28.1`, `dagre@0.8.5`, `cytoscape-dagre@2.5.0` and `mermaid@10`; nothing is vendored, so opening the map needs a connection.
- Mermaid draws: the Database ERD (an `erDiagram` source built by `buildDbErdMermaidSource()`, with `wireDbErdEntityClicks()` attaching entity clicks after `mermaid.run()` resolves), the diagram group of sequence/temporal diagrams (`<pre class="mermaid">` from the diagram's own source, with pan and a CSS-scale zoom fallback), and every fenced ` ```mermaid ` block inside a rendered README (`mdBlockToHtml()` emits `<pre class="mermaid">`, then `mermaid.run`).
- Cytoscape with dagre draws the graph-shaped diagrams (Module Dependencies, SPI Map, Bounded Contexts). `parseMermaidGraph()` parses the repository's Mermaid dialect (`graph`/`flowchart`) for the groups listed in `GRAPH_TYPE_KEYS` (`01-module-dependencies`, `02-spi-map`, `bounded-contexts`).
- The markdown export builds Mermaid text without the library (`buildModuleDependencyMermaid()`, `buildSpiMapMermaid()`, `buildContextMapMermaidSource()`, `buildDbErdMermaidSource()`), for pasting into GitHub documents.
- Outside the map, 22 markdown files contain ` ```mermaid ` blocks (the `Flow` diagrams that the script-group README standard requires, the root `README.md`, `INFRASTRUCTURE.md`, files under `.claude/`); they are drawn by GitHub or the editor, not by this page.

## Why change

The user wants the architecture map reworked without Mermaid (2026-10-23, raised while choosing a drawing approach for [improvement-212](improvement-212-api-flow-runner-page.md): the Mermaid 12.2.0 minified file alone is 5,494,801 bytes).

## Expected benefit

One rendering engine for the map instead of two, and one fewer library fetched from the network when the page opens.

## Approach

Item 1 — remove Mermaid from the page. What each current use needs, to settle in this task (the sequence-diagram group and the README blocks are the open questions):

1. **Database ERD:** needs a table/column renderer; options are HTML tables per entity with foreign-key links, or Cytoscape nodes carrying the column list. The data already comes live from `MODEL.dbErd`, so only the picture changes.
2. **Sequence/temporal diagrams:** verify which of these diagrams exist today and where their source lives; options are an own SVG renderer, a numbered step table, or dropping the group.
3. **Fenced `mermaid` blocks in README text:** options are showing them as code blocks, or a small own renderer for the repository's flowchart dialect; the README standard still requires the Mermaid `Flow` section in the files themselves, so those files do not change.
4. **Markdown export:** the Mermaid text it produces needs no library; decide whether to keep that output format.
5. **`parseMermaidGraph()`:** check whether it can be replaced by building the graph from the model data directly.

Further refactoring items are to be added here by the user.

## Plan (2026-11-04, executed: item 1 is done, the task stays open for further items)

Verified against the generator and the generated model on 2026-11-04. The scope is smaller than the Approach above assumed:

- The "sequence/temporal diagram group" no longer exists: the model has four diagram groups (Bounded Contexts 3, SPI Map 10, Module Dependencies 1, Database ERD 1) and the page has no `sequenceDiagram`. The generic `else` branch that renders a diagram with `<pre class="mermaid">` is dead code.
- Cytoscape with dagre already draws every graph-shaped diagram, through `parseMermaidGraph()`, which understands only `graph`, `subgraph id["..."]`, `id["label"]` rectangles and the `-->` / `-.->` edges with `|label|`.
- Mermaid is really used for two things: the Database ERD (an `erDiagram` built by `buildDbErdMermaidSource()`, 18 tables, with `wireDbErdEntityClicks()` attaching clicks after `mermaid.run()`), and the fenced mermaid blocks of README files shown inside the map (`mdBlockToHtml()`). 19 blocks in 19 markdown files, all `flowchart` (12 `TD`, 7 `LR`): rectangle `[..]` 163 uses, decision diamond `{..}` 35, cylinder `[(..)]` 2; edges `-->` 122, `-->|label|` 84, `-.->` 1, `-- text -->` 1; one `subgraph`, one `direction`.
- The ERD page already lists every table with columns, types, constraints, foreign keys and indexes below the diagram (`renderDbErdTableSchemas()`), so the picture only has to show tables and relationships.
- The markdown export builds Mermaid text without the library, for pasting into GitHub; the READMEs keep their ` ```mermaid ` blocks because the README standard requires them and GitHub draws them.

Decisions (recommendation first):
1. ERD form: Cytoscape nodes named after the tables with a small badge for the owning module, solid edges for real foreign keys labelled with the column, dashed edges for the conceptual relationships, a click scrolls to the table's schema section (as today). Alternatives: nodes carrying the column list (tall, 18 tables of about 10 columns each, unreadable), or HTML cards without a graph.
2. README flow blocks: draw them with the same Cytoscape engine, after extending the parser to the `flowchart` header, `{..}` diamonds, `[(..)]` cylinders, `-- text -->` and `direction`. Alternatives: show the blocks as plain code (loses the pictures), or keep Mermaid for these blocks only (the page keeps the library, the goal is not met).
3. Keep the Mermaid text in the markdown export (it needs no library and GitHub renders it).
4. Out of scope: vendoring Cytoscape and dagre so the page works offline (three `unpkg` scripts remain); a separate entry.
5. Record the decision with `/record-decision` for `docs/architecture/scripts` (it replaces the earlier choice to draw some diagrams with Mermaid's own engine).

Steps:
1. Parser: extend `parseMermaidGraph()` (name kept or renamed) to accept the `flowchart TD|LR` header and `direction`, the three node shapes, and the extra edge forms; node `shape` goes into the node data. Check by running it over all 19 blocks and comparing node and edge counts with a count taken from the source text.
2. Render every README flow block as its own Cytoscape instance: make `renderCytoscapeFromGraph()` take its container and return the instance instead of using the global `diagram-cy`; `mdBlockToHtml()` emits a container with the block's source in a data attribute; the screens that call `mermaid.run()` call a new `renderFlowBlocks()` instead.
3. ERD: new `renderDbErdGraph()` with the table nodes and relationships from `MODEL.dbErd`; keep `enableDragToPan` / zoom controls only if the Cytoscape view needs them; click handler scrolls to `db-table-<name>`.
4. Remove Mermaid: the `<script>` tag, `mermaid.initialize`, every `mermaid.run`, `wireDbErdEntityClicks`, the dead `else` branch and the comments that explain the old flow. The export builders stay.
5. Screenshot script: add two screens (Database ERD, one README page with flow blocks) so the result can be looked at.
6. `/record-decision` for `docs/architecture/scripts`; regenerate the ADR index; one line in the script group's README only if it names Mermaid as the renderer.
7. Verify: `bash docs/architecture/scripts/generate-architecture-model.sh`; `grep -c -i mermaid` shows only the export builders; the generated page loads in the headless browser with no console error; the count of Cytoscape containers on the README pages equals the count of blocks; the ERD shows 18 table nodes and as many edges as `buildDbErdMermaidSource()` has relationships; look at the screenshots; `/check-architecture-map`; `check-architecture-model-freshness.sh`. No Java changes, so no Maven run is needed.
