# improvement-229: Static reports on the architecture map's Code Quality screen

**Type:** improvement — new cards and tables on an existing generated page, plus a shared session ID for scripts
**Module:** `docs/architecture/scripts/generate-architecture-model.sh` (`renderCodeQuality()`, `test_reports_json()`, `run_logs_json()`), generated `docs/architecture/data/architecture-model.json` and `docs/architecture/architecture-map.html`, producers `scripts/build-and-test/`, `scripts/sonar/`, `scripts/ci/`, `playwright/run.sh`, new `scripts/utils/session-id.sh`
**Priority:** 🟡 Top — right after improvement-227, at the user's request (2026-10-26).
**When:** independent. Do not run while another task edits `generate-architecture-model.sh`.

## Goal

The architecture map's Code Quality screen shows the project's test and quality reports, so that after a test run you can see what happened (Playwright report, JaCoCo coverage, Surefire results, run logs) without knowing where the files are.

## Decisions (user, 2026-10-26)

1. Cards go directly on the existing Code Quality landing, next to Sonar and ArchUnit.
2. Cards are plain relative links: no existence check, no "report missing" message.
3. Reports (JaCoCo, Surefire) are **always** read from disk and shown with real data. No opt-in flag. If tests were never run the screens show an empty state.
4. JaCoCo HTML is generated by the build (copy of `target/site/jacoco/` per module, `--html` on the integration aggregate). The flat `jacoco/*.xml` stay because Sonar reads them.
5. Only the top-level reports folder is read. Per-stage copies (`advertisement-build-only-*`) and `it-mirror` are ignored by the Coverage and Tests tables.
6. Coverage colors: red at 60% and below, yellow up to 75%, green above 75%.
7. Run logs: one table per folder, built dynamically from `scripts/logs/**` and `scripts/ci/reports/`; new folders appear without a code change.
8. Run ID is a **session ID**: one per top-level script run, inherited by every script it calls. Manual runs: `YYYYMMDDHHMMSS` (UTC). CI runs: the Dagu run id (`ci-...`), passed to every Dagu step as the `session_id` param, so the map links back to the Dagu history. Logs from before this change show `-`.
9. The Tests table has no "Files" column (no benefit).
10. The freshness check no longer runs after every generation (it compared two identical generations). It stays as a manual check, ignores the `testReports` and `runLogs` sections, and is available as `/check-architecture-map`.
11. The wrong log-folder texts in the docs are fixed in this task.
12. Logs and reports are not committed (`.gitignore` covers `scripts/logs/`, `scripts/build-and-test/reports/`, `scripts/ci/reports/`); only the map and the model carry their numbers.

## What the screens look like now

- **Code Quality landing:** eight cards. Playwright report (link), Coverage, Tests, Run logs (screens).
- **Coverage:** per module line %, branch %, run time and a link to that module's HTML report; one more row for the integration aggregate.
- **Tests:** per module tests, failed, errors, skipped, time (s), run time; failing test classes listed below with links to their `.txt` files. No "Files" column.
- **Run logs:** one table per folder (Run ID = session ID, Started UTC, Files with notes) and a Dagu UI block at the end.
