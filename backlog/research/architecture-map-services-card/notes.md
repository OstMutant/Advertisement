## Findings

- Port consumers found: 9333 in docker-compose.seaweedfs.yml (literal) AND scripts/deploy-and-run/run.sh (SEAWEEDFS_CONSOLE_PORT default 9333, used by the real deploy path, which runs plain docker run, not compose); 8082 in scripts/ci/run.sh (UI_PROXY_PORT) and scripts/ci/dagu-rest-run-monitor.py (DAGU_UI_PORT default); 9099 in docker-compose.sonar.yml, scripts/sonar/run.sh (SONAR_URL and a hardcoded URL inside its Python heredoc), sonar-project.properties (sonar.host.url), .claude/agents/sonar/ensure-token-and-launch.sh (SONARQUBE_URL default), .claude/agents/sonar/sonar-analyst.md (MCP env literal), generator SONAR_URL; 8081 in deploy run.sh (APP_PORT default), playwright/run.sh and playwright.config.js (APP_URL default).
- No .bat file holds any of these port literals (grep of scripts/*.bat): .bat counterparts need no change.
- scripts/deploy-and-run/run.sh already reads .env into ENV_* prefixed vars so that an exported override (ci.yaml's isolated e2e stack: APP_PORT=18081, SEAWEEDFS_CONSOLE_PORT=19333) wins; new keys must use the same pattern: VAR=${VAR:-${ENV_VAR:-default}}. Reusing the existing names APP_PORT and SEAWEEDFS_CONSOLE_PORT in .env keeps ci.yaml untouched.
- Sonar compose is called as 'docker compose -f <file>' with no --project-directory (scripts/sonar/run.sh:124, scripts/utils/ensure-sonar-token.sh:32,47,48). Compose looks for .env in the project directory = the compose file's folder (scripts/sonar/), so ${SONAR_PORT} would resolve empty. Adding --project-directory would change the project name from 'sonar' to the repo folder name and orphan the sonar_sonarqube_* volumes (scan history); --env-file "$ROOT/.env" reads the root .env without changing the project name.
- ADR-003 (docs/architecture/scripts) title counts '3 entry-point cards'; ADR-023 and ADR-024 each added a System card through a new ADR and never annotated ADR-003. renderSystem()'s comment also says '3 entry-point cards' and cites ADR-003 by number; screenshot-architecture-map.sh comment says 'must show only 3 cards'.
- INFRASTRUCTURE.md is itself rendered inside the map (MODEL.rootInfrastructure on the Tooling & Pipelines screen); its Local Services table and app-startup table repeat 8081/9099/8082/9333 and the Swagger path. .claude/skills/app-readme-standards/SKILL.md mandates the services table with a local link per row and tells the editor to read compose files and scripts/ci/run.sh for ports (not .env).
- scripts ADR-009 (scripts/DECISIONS.md) already decided the repo-root .env as the home of DB/S3 values, the ENV_* fallback-tier pattern (explicit env wins, .env next, literal last-resort default) and that container-internal ports and doc mentions stay literal. Moving the service ports is a continuation of that decision; /record-decision says to extend or supersede an existing entry for a continuation, not to add a new number.
- Beyond the brief's list, APP_PORT has client-side defaults: playwright/run.sh and playwright.config.js (APP_URL default http://localhost:8081), docs/api-collections/scripts/check-collection.config.json (baseUrl), the Postman collection's host variable and api-collection-tests.sh header. All are already overridable (APP_URL / baseUrl argument); the plan leaves them and lists them as a decision.
- Adjacent issue (not in scope): root CLAUDE.md and INFRASTRUCTURE.md dev-mode command 'docker-compose -f scripts/deploy-and-run/docker-compose.db.yml -f ...seaweedfs.yml up -d' has no --project-directory, which rules/scripts.md says resolves the .env variables to empty strings. The new SEAWEEDFS_CONSOLE_PORT makes this command fail the same way the existing DB_PORT/S3_PORT already do.
- Stop rule: the official Compose docs settle the only technical unknown (how a compose file outside the root reads the root .env and what renames a project); the rest of the work is the project's own code and rules, and further web sources would not change the choice. Stopped after 7 sources.

## Variants and comparison

- V1 (chosen by the brief, kept): generator reads ports from .env, the per-service metadata (label, path, start script, condition, description) sits in one small table inside the generator, written into architecture-model.json as 'services'. Static, no runtime, follows the map's 'render only JSON' rule; least code.
- V2 (Homepage-style): metadata as labels on containers, discovered at runtime via the Docker socket. Rejected: needs a running dashboard process; the app (deploy-and-run run.sh) and Dagu proxy (ci/run.sh) are started with docker run, not compose, so labels would be spread over three mechanisms; contradicts the brief's static generation.
- V3: metadata as structured comments next to each port in .env. Rejected for the plan: a hidden parse convention inside a file that compose, Java (SharedEnvConfig) and three shell parsers read; puts URL paths (not config) into the config file. V4: a separate services.json data file: one more hand-written file with no gain over a table inside the generator, which already holds static text (Key Observations, PIPELINE_GROUPS).
- Generator reads .env only, never the caller's shell env, so check-architecture-model-freshness.sh gives the same JSON in ci-runner (where e2e overrides like APP_PORT=18081 are exported inline) as on the host. A missing key fails generation (fail fast) instead of rendering an empty port.
- Sonar compose: chosen --env-file "$ROOT/.env" on every 'docker compose -f docker-compose.sonar.yml' call (4 call sites). Alternative: --project-directory "$ROOT" plus a top-level 'name: sonar' in the compose file (keeps volumes, matches the deploy-and-run compose convention, one more line in the file). Both reach the goal; --env-file is the smaller change.

## Differences from the project

- CONFLICT (raise early): the brief asks to annotate or supersede ADR-003 for the sixth card; /record-decision forbids appending Amendment/Correction sections to an old entry (supersede instead) and its worthiness gate says a change to architecture-map.html's own card layout is not ADR-worthy; precedent ADR-023/ADR-024 added cards via new ADRs and left ADR-003 untouched. Root CLAUDE.md says 'update or annotate the existing entry'. Options for the person: (a) supersede ADR-003 with a count-free restatement, (b) reword ADR-003's title in place to drop the count, (c) leave ADR-003 and record nothing for the card.
- Project practice (ADR-009, deploy-and-run run.sh) keeps a last-resort literal default in shell scripts after the .env tier, e.g. ${DB_PORT:-${ENV_DB_PORT:-5432}}. Strict one-home would drop the literal and fail when .env is missing. Plan keeps the project's way for scripts; the generator (new code, never overridden by CI) reads .env only and fails fast.
- INFRASTRUCTURE.md: app-readme-standards skill requires the Local Services table with a local link per row and is kept current by a manual procedure; ADR-009 left doc mentions literal. Strict one-home would make the table name the .env key and point at the map's Services screen. INFRASTRUCTURE.md is itself rendered inside the map, so today's table plus the new screen show the same addresses twice on one page set.
- Sonar compose: project practice for compose files outside the repo root is --project-directory (rules/scripts.md). Applied to the sonar compose it would rename the project from 'sonar' to the repo folder name and orphan sonar_sonarqube_* volumes, so the plan pairs it with a top-level 'name: sonar' (Compose precedence: name: beats the project-directory basename). The smaller alternative, --env-file "$ROOT/.env", differs from the project's practice and is left as a decision.
